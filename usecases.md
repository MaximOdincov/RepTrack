# Диаграмма вариантов использования (Use Case Diagram)

## Актеры

| Актер | Описание |
|-------|----------|
| **Неавторизованный пользователь** | Пользователь на экране входа/регистрации, который ещё не выбрал способ использования приложения |
| **Гость** | Пользователь, выбравший "Продолжить как гость" — может работать с тренировками, упражнениями и шаблонами локально без синхронизации |
| **Авторизованный пользователь** | Пользователь, прошедший аутентификацию, имеет полный доступ ко всем функциям включая синхронизацию, профиль и социальные функции |

---

## Варианты использования (Use Cases)

### Группа: Аутентификация

#### UC1 — Войти в систему (Login)

**Описание:** Пользователь входит в существующий аккаунт, используя email и пароль.

**Предусловия:**
- Приложение установлено на устройстве
- У пользователя уже есть зарегистрированный аккаунт
- Устройство имеет подключение к интернету

**Основной сценарий:**
1. Пользователь открывает приложение
2. Система отображает экран входа (Sign In screen)
3. Пользователь вводит свой email в поле "Email"
4. Пользователь вводит свой пароль в поле "Password"
5. Пользователь нажимает кнопку "Sign In"
6. Система валидирует введённые данные
7. Система отправляет запрос на сервер для проверки учётных данных
8. Сервер подтверждает корректность данных
9. Система сохраняет токен авторизации локально
10. Пользователь перенаправляется на главный экран

**Альтернативные сценарии:**
- **A1:** Неверный формат email → Ошибка "Invalid email format"
- **A2:** Пустые поля → Подсветка незаполненных полей
- **A3:** Неверный email или пароль → Ошибка "Invalid credentials"
- **A4:** Нет подключения к интернету → Ошибка "No internet connection"

**Постусловия:**
- Пользователь успешно авторизован
- Токен доступа сохранён локально
- Главный экран приложения отображается

---

#### UC2 — Зарегистрироваться (Register)

**Описание:** Новый пользователь создаёт аккаунт в приложении.

**Предусловия:**
- Приложение открыто
- У пользователя нет зарегистрированного аккаунта
- Устройство имеет подключение к интернету

**Основной сценарий:**
1. Пользователь открывает приложение
2. Система отображает экран входа
3. Пользователь нажимает "Don't have an account? Sign up"
4. Система отображает экран регистрации
5. Пользователь вводит имя (минимум 3 символа)
6. Пользователь вводит email
7. Пользователь вводит пароль (минимум 6 символов)
8. Пользователь подтверждает пароль
9. Пользователь принимает соглашение GDPR
10. Пользователь нажимает "Sign Up"
11. Система валидирует данные
12. Система создаёт аккаунт в Firebase Authentication
13. Система создаёт документ пользователя в Firestore
14. Пользователь перенаправляется на главный экран

**Альтернативные сценарии:**
- **A1:** Имя короче 3 символов → Ошибка валидации
- **A2:** Пароли не совпадают → Ошибка "Passwords do not match"
- **A3:** Email уже зарегистрирован → Ошибка "Email already in use"

**Постусловия:**
- Аккаунт создан
- Данные пользователя сохранены в Firestore

---

#### UC3 — Сбросить пароль (Reset Password)

**Описание:** Пользователь восстанавливает доступ к аккаунту, если забыл пароль.

**Предусловия:**
- Приложение открыто на экране входа
- Устройство имеет подключение к интернету

**Основной сценарий:**
1. Пользователь нажимает "Forgot password?"
2. Система отображает экран сброса пароля
3. Пользователь вводит свой email
4. Пользователь нажимает "Reset Password"
5. Система отправляет письмо со ссылкой для сброса
6. Система отображает сообщение "Password reset email sent"
7. Пользователь переходит по ссылке в письме
8. Пользователь вводит новый пароль
9. Пароль обновлён в Firebase Authentication
10. Пользователь входит с новым паролем

**Альтернативные сценарии:**
- **A1:** Неверный формат email → Ошибка валидации
- **A2:** Нет подключения к интернету → Ошибка "No internet connection"

**Постусловия:**
- Письмо со ссылкой сброса отправлено
- Пароль изменён (если пользователь перешёл по ссылке)

---

#### UC4 — Продолжить как гость (Continue as Guest)

**Описание:** Пользователь решает использовать приложение без регистрации.

**Предусловия:**
- Приложение открыто на экране входа

**Основной сценарий:**
1. Пользователь нажимает кнопку "Continue as guest"
2. Система создаёт локального пользователя с флагом `isGuest = true`
3. Система отображает предупреждение о лимитах режима гостя
4. Пользователь подтверждает продолжение
5. Система перенаправляет на главный экран
6. Включается guest mode

**Постусловия:**
- Пользователь находится в режиме гостя
- Данные сохраняются только локально
- Функции синхронизации и社交 features скрыты

### Группа: Тренировки (Доступно Гостю и Авторизованному пользователю)

#### UC5 — Просмотреть тренировочные сессии (View Workout Sessions)

**Описание:** Пользователь просматривает свои тренировки на календаре, видит запланированные, активные и завершённые сессии.

**Предусловия:**
- Пользователь авторизован или является гостем
- База данных доступна

**Основной сценарий:**
1. Пользователь открывает приложение
2. Система отображает главный экран с календарём
3. Календарь показывает текущий месяц с индикаторами тренировок:
    - 🟢 Запланированные (PLANNED)
    - 🟡 Активные (IN_PROGRESS)
    - 🔵 Завершённые (COMPLETED)
4. Под календарём отображается список тренировок для выбранной даты
5. Каждая карточка показывает название, статус, количество упражнений
6. Пользователь может переключаться между датами

**Альтернативные сценарии:**
- **A1:** Нет тренировок на дату → Сообщение "No workouts for this date"

**Постусловия:**
- Календарь с тренировками отображается
- Можно перейти к созданию или выполнению тренировки

---

#### UC6 — Добавить упражнение в сессию (Add Exercise to Session)

**Описание:** Пользователь добавляет упражнение из библиотеки в текущую тренировочную сессию.

**Предусловия:**
- Пользователь находится на экране выполнения тренировки
- В библиотеке есть упражнения

**Основной сценарий:**
1. Пользователь находится на экране тренировки
2. Пользователь нажимает кнопку "Add Exercise"
3. Система открывает библиотеку упражнений в режиме выбора
4. Пользователь выбирает упражнение
5. Система добавляет упражнение в тренировку
6. Система создаёт запись WorkoutExercise в базе данных

**Постусловия:**
- Упражнение добавлено в тренировку
- База данных обновлена

---

#### UC7 — Удалить упражнение из сессии (Remove Exercise from Session)

**Описание:** Пользователь удаляет упражнение из текущей тренировочной сессии.

**Предусловия:**
- Пользователь находится на экране тренировки
- В тренировке есть хотя бы одно упражнение

**Основной сценарий:**
1. Пользователь делает свайп влево на упражнении в списке
2. Система отображает кнопку "Delete"
3. Пользователь нажимает "Delete"
4. Система отображает диалог подтверждения
5. Пользователь подтверждает удаление
6. Система удаляет упражнение из тренировки (каскадно удаляются подходы)
7. Система обновляет список упражнений

**Постусловия:**
- Упражнение удалено из тренировки
- Все подходы этого упражнения удалены
- База данных обновлена

---

#### UC8 — Добавить шаблон в сессию (Add Template to Session)

**Описание:** Пользователь добавляет все упражнения из шаблона в текущую тренировочную сессию.

**Предусловия:**
- Пользователь находится на экране тренировки
- В библиотеке есть хотя бы один шаблон

**Основной сценарий:**
1. Пользователь находится на экране тренировки
2. Пользователь нажимает кнопку "Add Template"
3. Система открывает экран списка шаблонов
4. Пользователь выбирает шаблон
5. Система копирует все упражнения из шаблона в тренировку
6. Система создаёт записи WorkoutExercise для каждого упражнения
7. Система возвращает на экран тренировки

**Постусловия:**
- Упражнения из шаблона добавлены в тренировку
- База данных обновлена

### Группа: Упражнения (Доступно Гостю и Авторизованному пользователю)

#### UC9 — Просмотреть упражнения (View Exercises)

**Описание:** Пользователь просматривает библиотеку упражнений, фильтрует и ищет нужные упражнения.

**Предусловия:**
- Пользователь авторизован или является гостем

**Основной сценарий:**
1. Пользователь нажимает на вкладку "Library"
2. Система отображает экран библиотеки упражнений
3. Упражнения сгруппированы по категориям мышц:
    - Chest (Грудь)
    - Back (Спина)
    - Legs (Ноги)
    - Arms (Руки)
    - Abs (Пресс)
    - Cardio (Кардио)
4. Пользователь может искать упражнения через строку поиска
5. Пользователь может фильтровать по группе мышц

**Альтернативные сценарии:**
- **A1:** База данных пуста → Сообщение "No exercises found" и кнопка "Add exercise"

**Постусловия:**
- Библиотека упражнений отображается
- Можно перейти к созданию или редактированию

---

#### UC10 — Создать упражнение (Create Exercise)

**Описание:** Пользователь создаёт новое упражнение в библиотеке.

**Предусловия:**
- Пользователь авторизован или является гостем

**Основной сценарий:**
1. Пользователь находится на экране библиотеки упражнений
2. Пользователь нажимает FAB кнопку (+)
3. Система отображает экран создания упражнения
4. Пользователь вводит название упражнения
5. Пользователь выбирает группу мышц
6. Пользователь выбирает иконку упражнения
7. Пользователь optionally вводит описание
8. Пользователь нажимает "Save"
9. Система валидирует данные
10. Система сохраняет упражнение в Room
11. Если пользователь авторизован — синхронизирует с Firestore

**Альтернативные сценарии:**
- **A1:** Пустое название → Ошибка "Exercise name is required"
- **A2:** Не выбрана группа мышц → Ошибка "Muscle group is required"

**Постусловия:**
- Упражнение создано в базе данных
- Синхронизировано с облаком (если авторизован)

---

#### UC11 — Редактировать упражнение (Edit Exercise)

**Описание:** Пользователь изменяет параметры существующего упражнения.

**Предусловия:**
- Упражнение существует в базе данных

**Основной сценарий:**
1. Пользователь делает long press на упражнении
2. Система отображает контекстное меню: Edit, Delete
3. Пользователь выбирает "Edit"
4. Система отображает экран редактирования с предзаполненными данными
5. Пользователь изменяет нужные поля
6. Пользователь нажимает "Save"
7. Система обновляет упражнение в базе данных
8. Система синхронизирует изменения с Firestore (если авторизован)

**Постусловия:**
- Упражнение обновлено
- Изменения синхронизированы (если авторизован)

---

#### UC12 — Удалить упражнение (Delete Exercise)

**Описание:** Пользователь удаляет упражнение из библиотеки.

**Предусловия:**
- Упражнение существует в базе данных

**Основной сценарий:**
1. Пользователь делает long press на упражнении
2. Система отображает контекстное меню: Edit, Delete
3. Пользователь выбирает "Delete"
4. Система отображает диалог подтверждения
5. Система проверяет, используется ли упражнение в тренировках/шаблонах
6. Если не используется — удаляет упражнение
7. Если используется — предупреждает и предлагает удалить из связанных сущностей
8. Пользователь подтверждает
9. Система удаляет упражнение из базы данных
10. Система синхронизирует удаление (если авторизован)

**Постусловия:**
- Упражнение удалено из базы данных
- Связанные записи обновлены или удалены

#### UC14 — Создать шаблон (Create Template)

**Описание:** Пользователь создаёт новый шаблон тренировки с возможностью настройки дней недели для автоматического добавления.

**Предусловия:**
- Пользователь авторизован или является гостем
- В библиотеке есть хотя бы одно упражнение

**Основной сценарий:**
1. Пользователь находится на экране списка шаблонов
2. Пользователь нажимает FAB кнопку (+)
3. Система отображает экран создания шаблона
4. Пользователь вводит название шаблона
5. Пользователь optionally добавляет описание
6. Пользователь нажимает "Add Exercises"
7. Система открывает библиотеку упражнений в режиме выбора
8. Пользователь выбирает упражнения
9. Система возвращает на экран создания с выбранными упражнениями
10. Пользователь настраивает порядок упражнений (drag & drop)
11. Пользователь настраивает параметры для каждого упражнения:
    - Количество подходов
    - Время отдыха
12. Пользователь optionally настраивает дни недели:
    - Выбирает дни (Mon, Tue, Wed, Thu, Fri, Sat, Sun)
    - При выборе дней шаблон будет автоматически добавляться в календарь на эти дни
13. Пользователь нажимает "Save"
14. Система создаёт WorkoutTemplate в базе данных
15. Система создаёт связанные TemplateExercise записи
16. Если выбраны дни недели — система создаёт тренировки на ближайшие выбранные даты
17. Система синхронизирует с Firestore (если авторизован)

**Альтернативные сценарии:**
- **A1:** Пустое название → Ошибка "Template name is required"
- **A2:** Нет выбранных упражнений → Ошибка "Add at least one exercise"

**Постусловия:**
- Шаблон создан в базе данных
- Если настроены дни недели — тренировки созданы в календаре
- Синхронизировано с облаком (если авторизован)

### Группа: Подходы (Доступно Гостю и Авторизованному пользователю)

#### UC17 — Записать результат подхода (Record Set Result)

**Описание:** Пользователь записывает вес и повторения для выполненного подхода.

**Предусловия:**
- Пользователь находится на экране выполнения упражнения
- Тренировка в статусе IN_PROGRESS

**Основной сценарий:**
1. Пользователь нажимает на упражнение в тренировке
2. Система отображает экран упражнения с таблицей подходов
3. Пользователь нажимает "Add Set"
4. Система добавляет новую строку подхода
5. Пользователь вводит вес (кг)
6. Пользователь вводит количество повторений
7. Пользователь выполняет подход
8. Пользователь отмечает подход как выполненный (checkbox)
9. Система записывает время выполнения (completedAt)
10. Система автоматически запускает таймер отдыха
11. Подход сохранён в базе данных

**Постусловия:**
- Подход создан и сохранён в базе данных
- Таймер отдыха запущен

### Группа: Таймер и статистика (Доступно Гостю и Авторизованному пользователю)

#### UC20 — Запустить таймер (Start Timer)

**Описание:** Пользователь запускает таймер отдыха между подходами или таймер тренировки.

**Предусловия:**
- Пользователь находится на экране выполнения упражнения

**Основной сценарий (Таймер отдыха):**
1. Пользователь завершает подход (отмечает как выполненный)
2. Система автоматически запускает таймер отдыха (по умолчанию 60 секунд)
3. Система отображает обратный отсчёт
4. Пользователь отдыхает
5. По окончании таймера система издаёт звуковой сигнал
6. Пользователь может нажать "Skip" для пропуска таймера

**Основной сценарий (Таймер тренировки):**
1. Пользователь начинает выполнение тренировки
2. Система автоматически запускает общий таймер тренировки
3. Таймер отображается в верхнем углу экрана
4. При завершении тренировки таймер останавливается
5. Итоговое время сохраняется в поле durationSeconds

**Постусловия:**
- Таймер запущен/остановлен
- Время зафиксировано в базе данных

#### UC21 — Просмотреть статистику по упражнению (View Exercise Statistics)

**Описание:** Пользователь просматривает статистику прогресса для конкретного упражнения.

**Предусловия:**
- Упражнение существует в базе данных
- Есть хотя бы одна выполненная тренировка с этим упражнением

**Основной сценарий:**
1. Пользователь находится на экране библиотеки упражнений
2. Пользователь нажимает на упражнение
3. Система отображает экран деталей упражнения
4. Система показывает статистику:
    - Общее количество подходов за всё время
    - Общий объём работы (сумма вес × повторения)
    - Лучший результат (максимальный вес в одном подходе)
    - График прогресса по датам
    - История последних тренировок с этим упражнением
5. Пользователь может фильтровать по периодам (неделя/месяц/год/всё время)

**Альтернативные сценарии:**
- **A1:** Нет данных → Сообщение "No statistics available yet"

**Постусловия:**
- Статистика отображается на экране
- Пользователь видит прогресс по упражнению

### Группа: Только для Авторизованного пользователя

#### UC23 — Синхронизировать данные (Sync Data)

**Описание:** Пользователь инициирует синхронизацию с облаком.

**Предусловия:**
- Пользователь авторизован
- Устройство имеет подключение к интернету

**Основной сценарий:**
1. Пользователь находится на экране профиля
2. Пользователь нажимает кнопку "Sync Now"
3. Система проверяет подключение к интернету
4. Система отображает индикатор прогресса
5. Система выполняет двустороннюю синхронизацию:
    - Upload локальных изменений в Firestore
    - Download изменений из Firestore
    - Conflict resolution (Last Write Wins)
6. Система обновляет статус "Last sync: [date/time]"
7. Система отображает результат синхронизации

**Альтернативные сценарии:**
- **A1:** Нет подключения к интернету → Ошибка "No internet connection"
- **A2:** Сервер недоступен → Ошибка "Sync service unavailable"

**Постусловия:**
- Данные синхронизированы между локальной базой и Firestore
- Статус синхронизации обновлён

#### UC25 — Добавить друга (Add Friend)

**Описание:** Пользователь добавляет другого пользователя в друзья.

**Предусловия:**
- Пользователь авторизован
- Устройство имеет подключение к интернету

**Основной сценарий:**
1. Пользователь находится на экране профиля
2. Пользователь нажимает кнопку "Friends"
3. Система отображает экран друзей
4. Пользователь нажимает "Add Friend"
5. Система отображает диалог поиска
6. Пользователь вводит email или username друга

**Альтернативные сценарии:**

## Приложение: Термины и определения

| Термин | Определение |
|--------|-------------|
| **Неавторизованный пользователь** | Пользователь на экране входа/регистрации, который ещё не выбрал способ использования приложения |
| **Гость** | Пользователь, выбравший использование приложения без регистрации, с ограниченным функционалом |

| **Template** | Шаблон тренировки для повторного использования с возможностью настройки дней недели |
| **Firestore** | Облачная NoSQL база данных Firebase для синхронизации |
